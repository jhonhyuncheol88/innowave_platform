## 요약

"기존 프로젝트를 열면 데모가 보인다"는 제보로 시작해, 워크플로우 저장/복원 경로를 전면 점검. 저장 자체는 정상임을 Firestore 실측으로 확인했고, 실제 결함 4건(상태 회귀·명시 저장 부재·캐시 재조회 누락·유형 무관 데모 폴백)을 수정. 상태 회귀 방지 로직은 번들된 실제 코드로 단위 검증(4/4 PASS).

## 작업 상세

### 1. 저장 데이터 복원 (하이드레이션) — 오전
- 2단계: `events/{id}/programs` 저장본으로 프로그램 목록 복원 (+ 복원 중 로딩 표시)
- 3단계: `events/{id}/matches` 저장본으로 인력 선택 복원
- 4단계: 최신 저장 견적의 옵션(Basic/Standard/Premium) 복원
- 프로젝트 전환 감지 마커(`programsEventId` 등), "새 기획 시작" 시 `WORKFLOW_RESET` 전체 초기화
- 커밋 `870ba28`

### 2. 데이터 관리 분석 (Firestore 실측)
- admin SDK로 events 11건 + 서브컬렉션 실측: **사용자 프로젝트에는 programs 7·matches 2·quotes 1 정상 저장** — 쓰기 경로 건강
- 증상의 실체: **시드 프로젝트 10건은 워크플로우 데이터가 애초에 없음** → 빈 저장본이 해커톤 데모로 폴백되어 "그 프로젝트의 데이터"처럼 보였던 것
- 분석 중 실제 결함 4건 발견 (아래)

### 3. 결함 수정 (서브에이전트 2개 병렬)
- **① 상태 회귀 방지**: `saveWorkflowStep(eventId, status, step, extra)` 신설 — status/currentStep은 순위(draft→…→done)가 **앞으로 갈 때만** 갱신. Step1~4의 직접 patch 전부 교체. (기존엔 in_progress 프로젝트의 2단계를 수정하면 상태가 'matching'으로 후퇴)
- **② 2단계 명시 저장**: "저장" 버튼 + 미저장 변경 표시(주황 점) + "저장됨 ✓" 칩 — 다음 단계로 가지 않아도 저장 가능
- **③ 캐시 무효화 → 자동 재조회**: `useCacheStore`에 key별 세대(versions) 추가, 마운트된 `useAsyncData`가 invalidate를 감지해 조용히 refetch (키 변경 시엔 이전 값 즉시 폐기, 같은 키 재검증 시엔 유지해 깜빡임 방지)
- **④ 유형별 프로그램 초안**: `PROGRAM_DRAFTS` 8종(해커톤/부트캠프/데모데이/경진대회/네트워킹/포럼/특강/박람회) + `programDraftFor()`. 저장본 없는 프로젝트는 행사 유형에 맞는 초안 + *"아직 저장된 구성이 없어 AI 초안을 보여드립니다"* 배너. "해커톤 유형" 하드코딩 문구 → 실제 eventType
